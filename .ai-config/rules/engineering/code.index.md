# 设计模式 + 子 agent 复核 — AI 执行规范(route)

按需拉:引入抽象时 / 子 agent 复核时 / 拆分后。T0·一次性·临时排查脚本不开;老项目小改优先保持局部一致,不借机引新范式。判断在交互里成;工具能判的→registry;身份的设计+机械见 AGENTS.md §3·§5 + registry,本文件只补语义层。

## §1 应用证据闸(引入任何抽象的唯一闸)
引入任何抽象 MUST 产出三点,否则=没应用 → 回直写或沿用现风格:① 解决的具体复杂度(要有代码证据)② 真实代价(改多少文件 / 影响多少调用方 / 测试·迁移·回滚成本)③ 何时失效或变负担。**三点 MUST 用业务话**(这抽象让什么业务改动变便宜 / 防什么业务错),禁只报模式名(Strategy/Adapter…)——否则用户判不了值不值。每轮最多评 1-2 个主导抽象;说不清三点=不引。
闸同样管**任何"修复/加固"提议**(幂等键/锁/去重/合并/拆分/重构),不止抽象:MUST 同样产出三点,且**先证明该失败模式在当前部署/工作流真触发**(给触发条件,非「理论上会」),否则=过度设计 → 不改。默认尊重存量业务特殊设计、选最便宜的正确动作;「长得像坏味道/反模式」≠ 问题。

**契约设计(只对稳定核心严格):** 划 稳定核心(只增不改;`[机器]` schema-diff 拦改名/删/改类型)/ 流动前沿(圈 `experimental`·可 reshape·标勿依赖·闸豁免);字段长熟→晋升核心;承诺最少、别做太早太全。5 指引:承诺最少 / 类型即 oracle(`[机器]`) / 失败也是契约(定错误形状) / 不漏内部(`[机器]` 异常泄漏 semgrep) / 单一 owner。

**未来可拆分契约(`[机器]` Ruff TID252 + encapsulation):** 跨模块依赖只走稳定公开入口,禁相对 import、禁 import `_private`/`internal`/`impl`；前者由 Ruff、后者由项目小检查器拦。深 import、门面 re-export 缺 `__all__`、顶层副作用没有可靠通用裁判，不设高噪机器提示，交 cleanup 子 agent 按具体变更判断。学名:Facade(门面模式)——把外部能碰的入口收窄,以后内部搬家不拖着调用方一起改。

## §2 性能统一判据
写处理逻辑,锚点放「规模放大时会怎样」而非「眼前样例能否跑通」——答 n 最坏多大?work 随 n 怎么涨?不匹配(n 可能大 + 超线性或有重复)→ 不脑补谁快,`scratch/` 写一次性 bench 实测候选(跑完弃);n 有界→直接写。各种具体形态(如递归 DOM 深扫)都是这一条的实例。
- **默认埋计时**:多步流程/热路径给每步埋轻量计时,收尾**按耗时降序**打一行 slow-step 摘要——慢步自己浮出来,不靠脑补谁慢。

## §3 子 agent 复核(人触发体检:阶段 / 大清理;见 `rules/review/review.index.md`)
**五层优先级**(越上越影响架构、越没工具,审从上往下,上层没过别花力气下层):正本见 `rules/review/review.index.md` 的五层表;本文件只补设计语义和专项复核,不再复写工具清单以免漂移。**绿 sweep ≠ 架构无恙,只证 L4/L5;L1–L3 工具够不到,靠人触发的分层审。**
判定四档:通过 / 有限通过(列 defer) / 必须重构 / 无法判定(原因)→升级用户 或 标"需运行时验证"。判不出就说判不出、别猜(幂等/隔离级别取决于外部服务语义,读代码判不出;假自信结论比"不知道"更危险)。

编排按 blast-radius(用力分配见 AGENTS.md §4):
- 低(可逆/单点/无外部写)→ 单遍复核,别 fan-out 烧 token。
- 高(不可逆/上游被依赖/外部写/并发)→ 1-2 个独立子agent对抗证伪(2 个时各换一 lens:正确性 / 安全·并发);**任一证伪成立即降候选/推翻**——对抗本就宁可误杀,不搞多数表决(多数表决=宽容,与宁可误杀矛盾);判不出升级用户,不取"看起来对"。
- 一个 context 装不下(全仓审计/迁移/diff 比对)→ 按子任务 fan-out 读 → 每条结论再派独立 agent 对抗证伪 → 只有坐实的浮上来。
- 对抗校验=高 blast-radius 默认、非可选;收敛后只交坐实结论。
- Agent 工具临时审查同规:finder 找问题后 MUST 自跟一轮 refuter 反驳证伪;**未证伪的结论标「候选·未坐实」,不作定级结论、不据此动手**。子 agent 只读切片,默认把「像反模式」当结论,refuter 是抵消项、非可选。
- 发现坐实闸(每条 ≥中危发现的 `[强制产物]`):MUST 给 ① 真实触发条件——具体到部署模型/调用方/工作流(非「理论上会」)② 调用链或客观信号佐证;缺=未坐实 → 降「候选」。举证责任在发现方。
- 交付节奏(审查/审计结论 → 人裁决):**逐条交、一次一条**,每条标自身置信度/最可能错处;禁一次性甩多条定级结论(体量+自信措辞掩盖误报,人无法逐条核)。

高权重三项 → 要一个测试、不靠读代码(能跑出来的正确性别留给眼力):
| 项 | 要的测试(挂 pytest) | 判不出时 |
|---|---|---|
| 幂等性(有写入/调外部/DB) | 同输入连调 2 次,副作用计数=1 / 结果稳定 | 无法判定→需运行时验证 |
| 部分成功(批量) | 注入第 N+1 条失败,调用方能区分 全失败 vs 部分成功 + 回滚策略生效 | 无法判定→升级 |
| 返回结构**可判别** | 多分支(正常/异常/空/部分):调用方有稳定方式区分(相同顶层字段 **或** 判别 tag) | —— |

测试模板:
```python
# 幂等性:连调 2 次,副作用只一次、结果稳定
def test_<op>_idempotent():
    spy = install_side_effect_spy()      # DB 写/外部调用计数
    <op>(input); s1 = snapshot_state()
    <op>(input); s2 = snapshot_state()   # 模拟重试/重投/重复提交
    assert spy.effect_count == 1
    assert s1 == s2
# 部分成功:第 N+1 条失败,调用方可区分、回滚与声明一致
def test_<batch>_partial_failure():
    res = <batch>([ok, ok, BAD, ok])
    assert res.kind in ("all_failed", "partial")
    assert committed() == expected_for(res.kind)
```

其余复核字段:
- 坏味道 → 只查工具判不了的语义味道:命名不表达业务意图 / 重复**业务**逻辑。魔法数字·过长函数·深嵌套→radon·ruff·semgrep(registry),不在此重复。
- 代码身份(语义层)→ 入口是否**真薄** / 正式能力是否反依赖 tools·tests·archive·scripts·devtools / 非正式区带 `# lifecycle:` 身份(短命探针标 temp·长寿工具住 devtools/) / 存量是否新增正式能力。职责混杂或反依赖→不过。设计=AGENTS.md §3,机械=registry(inventory·lifecycle baseline 棘轮)。
- 取代纪律(语义层)→ 本切片给**已有能力**写了更好新实现 / 用户明示新策略:旧实现已删 / 新策略已落地否?同一业务能力两条 live 路径=SSOT 双源,不过(除非走放行登记:原因+可判定清除条件+日期)。判据=两条真实运行路径,非表面相似代码段(后者→坏味道)。设计=AGENTS.md §5 取代纪律。
- 防膨胀(语义层)→ 一次性验证是否直接调用、没专门留文件?新增测试/tool 每条能说出验哪个业务意图?有无死测试·重复用例·堆 tool 的杂物?被取代旧测试同切片删?给人命令交付前已自测能跑?设计=AGENTS.md §5 防膨胀。
- 错误信息 → 业务异常含 字段+期望+实际+用户下一步(反例:"未找到匹配记录"不达标,须到"订单缺失还是单价不符");catch 附业务上下文(批次/行号/关键字段)+栈;调试走 DEBUG+模块开关;多输出目标明确哪条进哪,不留日志断层。
- 可观测性只在项目模型明确声明 API、后台任务、队列或健康检查入口后审；通用层只要求失败可定位、外部调用有边界，不预设 HTTP 错误形状、request_id 或错误目录。具体协议由项目自己的契约和测试定义。
- 契约合规 → 符合验收动作/业务口径/SSOT;隐性假设已登记。
- 副作用风险 / 扩展性 / 设计模式(改成本高→记 defer 不强制) / 重构 ROI。

复核重点(静态工具覆盖不到):
- 真实运行路径闭合:正常/失败/取消/重试/并发/降级。
- 异步重试 MUST 区分"操作未发生" vs "已发生未完成"——恢复路径相反,用 URL/DOM/响应特征等客观信号判,不靠超时推断。
- 状态与数据生命周期:SSOT/缓存/写入顺序/脏数据/回滚。
- 公共行为:返回结构/异常语义/副作用/调用方兼容/迁移成本。
- 外部依赖边界:SDK/IO 是否穿透核心、可否替换/mock/隔离。

结论:四档之一。

## §4 拆分专项检查
**拆之前先判该不该拆——行数是信号、连通度才是裁判(光看行数=耍流氓)。** 当前机器闸只给 import-cycles、dup-symbol 等辅助证据；模块内函数调用图连通分量仍应按需用一次性探针取得，不得写成已接线硬闸。多个弱连通子簇(可无环切)=可拆;单一大连通块(如最大分量 ≥80%)=内聚不拆,登记为"内聚例外"豁免行数棘轮、别反复重审。行数超 600 只是"该看一眼"的触发,不是"该拆"的判据。
拆(确认可拆后)拆分后乐观运行(跑测试/调用方),实际与预期不符才进对应项,不逐项前置(run-and-observe,判断锚在可观测信号):
- 老调用 → 全局搜原 文件名/类名/函数名,逐一确认调用方更到新路径。
- 循环依赖 → 新文件间互相引用=边界划错,重新拍板。
- 接口完整性 → 原对外 export/public 在新文件全可寻,缺一=未完成。
- 重复逻辑 → 多文件相似段→合并公共模块,非各自复制。
- 测试覆盖 → 原测试仍过;依赖原结构的测试路径 MUST 同步更新。
- 兼容别名 → MUST 注释清理条件(`# 兼容别名:待 xxx 更新后删`)+闭包 defer 登记,不得无限期(生命周期见 AGENTS.md §3)。
- MRO 冲突 → 多继承/mixin 同名方法:优先删占位声明(`raise NotImplementedError` 在 mixin 是设计味,抽象该由 ABC 担);删不掉才调继承顺序,真相源 mixin 排占位 mixin 前。

## §5 分支闭包专项:死码 / 废弃逻辑清理复核(人触发大清理;死码用 git 年龄分诊:老=rot删/新=WIP宽限,仅作人审提示、非到期自动删)
触发=分支功能闭包(merge/PR 前),范围 `git diff main...HEAD`(非单切片)。why:切片复核只看自身 diff——切片1 建的符号被切片3 改废,两次切片复核都看不见;跨切片涌现的死码/双源只有分支级全 diff 能见。装闸而非留 `[启发]`:删旧码=成本现在·回报延迟,靠自律必烂。
机器先行(复核不碰机器能判的):跑 `check.py cleanup`(全量机器闸;具体清单见 `check.py list`,别在此枚举=会漂)。复核只接手 vulture 等机器判不出的语义层。
复核只接手 vulture 判不出的语义死码/废弃:
- 废弃但仍 live 的旧路径:新实现已上、旧路径仍有真实 caller=双源 SSOT(取代纪律 AGENTS.md §5);vulture 见有 caller 判不出"废弃",不过。
- 注册表/动态分发/反射僵尸:vulture 误判"可达",实则无真实触发 key / 无注册来源。
- 备选/fallback 僵尸:测试是唯一 caller,vulture 因测试 import 判可达。
- vulture 漏报兜底:min-confidence 80 以下未报的低置信死码。
- 孤儿文件(文件级):本分支新增/改动的整 .py 无人 import——vulture 漏「文件内 A↔B 互调、整文件零入边」的自洽孤岛;全局搜确认零 live 入边→候选删。高频后升 grimp import 图可达性机器闸(地基随 import-linter 已在)。
临时件清理哲学(别重造已删的轮子):项目**不设"过期日期"机器闸**——`# expires:`/superseded 那套已证 0 使用而删(见 `tools/check_lifecycle.py` 头)。临时件/旧码"该不该删"不靠自愿标日期,靠 vulture 死码 + 本复核取代判断;`lifecycle` 只管"有没有身份标注",不管"过期没"。分支闭包时本分支新增的 tmp/probes/ 件逐一问 删/转正/标身份(复核动作,非日期闸)。不设「优雅闸」:优雅=死码清零+依赖清晰+契约完整的涌现结果,无独立 oracle,设了=主观假闸。
误报闸(死码=假阳性重灾区,subagent 只读切片看不到动态/外部/反射 caller):每条"该删"MUST 走 §3 finder→refuter——标「候选·未坐实」→ refuter 全局搜证伪(证明真无 live caller、非仅本 diff 内)→ 套发现坐实闸(真实触发条件+调用链佐证)→ 人裁决才删。删码近不可逆,举证责任在发现方,宁漏删不误删。大 diff 装不下→按模块 fan-out(§3),每模块独立结论再汇。
产出(`[强制产物]`):四档结论 + 死码/废弃清单,每条→已删 或 放行登记(原因+可判定清除条件+日期);「候选·未坐实」不作删除依据。
